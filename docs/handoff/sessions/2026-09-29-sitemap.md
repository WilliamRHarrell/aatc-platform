# Session 2026-09-29: /sitemap.xml (branch feat/sitemap)

robots.ts has always pointed the production host at `/sitemap.xml`, but no
sitemap route existed, so that URL was a 404. Found in #52.

- `src/app/sitemap.ts` serves the file; `src/lib/sitemap.ts` builds the list
  and has no database access, so it can be unit-tested.
- Static pages: every value in `ROUTES` (src/lib/routes.ts) except
  /admin, /portal, /auth and /api, which are the same prefixes robots.txt
  disallows. A page added to ROUTES appears in the sitemap automatically.
- Dynamic pages: /directory/<id> for every approved exhibitor
  (applications_public with status approved, the same filter /directory
  uses), and /tattoo-battle/entry/<n> for buckets with a published entry
  (getPublishedEntries). Unpublished buckets are noindex holding pages, so
  they are left out.
- Every URL is on CANONICAL_ORIGIN (https://www.allamericantattooconvention.com)
  whatever host serves the file. Before cutover, robots.txt on the preview
  host is still disallow-all and does not list the sitemap. Flipping
  NEXT_PUBLIC_SITE_URL at cutover makes robots.txt list it; nothing else to
  do.
- Revalidates hourly (the battle-entries cache makes it refresh sooner).

Checks (local build, 2026-09-29): /sitemap.xml returns 200 as
application/xml with 27 URLs, all on www, and every one returns 200. There
are no published battle entries yet; 1 directory entry (13c265d7).
`npm test` passes 210/210, with 4 new sitemap tests.

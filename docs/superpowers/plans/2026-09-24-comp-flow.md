# Comp Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A comped booth application owes $0 in every surface (invoice, portal, emails, sweep, Assign Booth), the comp holds in any order of approve / send back / comp, and only an explicit "Remove comp" restores pricing.

**Architecture:** Migration 072 adds `applications.comped_at` / `comped_by` (one fact: comped = `comped_at is not null`), clamped for owners on insert and update, and two admin-only SECURITY DEFINER RPCs, `comp_application(uuid)` and `uncomp_application(uuid)`, that change the application and its invoice in one transaction. Comp settles the invoice (amount 0, status paid, deposit_paid_at and final_paid_at set), so every existing "deposit paid" gate (Assign Booth, directory policy, sweep joins) already treats it as paid; the sweep additionally guards on `comped_at is null`. Approve, when comped, sets no due dates and creates no invoice; send back to pending clears approved_at and both due dates. Emails: a comped approval variant and a one-off comp notice.

**Tech Stack:** Next.js 16, Supabase RLS + plpgsql RPCs, Resend, vitest (pure helpers), guardedWrite on browser writes.

**Spec:** Ryan's messages of 2026-09-24 (investigation findings accepted; decisions 1-5 in the go-ahead message).

## Decisions recorded (Ryan can overturn any)

- **D1. Milestones on comp.** `comp_application` sets `deposit_paid_at` and `final_paid_at` (Ryan's instruction), plus `paid_at`, amount 0, status paid, amount_paid 0. Payment method/reference untouched.
- **D2. Refusal rule.** `uncomp_application` raises `P0001` "payments exist" when `invoices.amount_paid > 0`.
- **D3. Uncomp restores** amount = `applications.total_amount`, status pending, milestones and paid_at null; if the application is approved, the drawer restores `deposit_due_at` = the LATER of `approved_at + 30 days` and `now + 14 days` (Ryan, 2026-09-24: a restored comp never lands already overdue) and `final_due_at = FINAL_DUE_AT`. Pure helper `restoredDepositDueAt(approvedAt, now)`, tested with an approval older than 30 days.
- **D4. Approve is idempotent on money.** `updateStatus('approved')` builds its payload through a pure helper `approvePayload(app, now)`: comped → `{ status, approved_at }` only; else the existing dates. Invoice creation only when none exists, unchanged.
- **D5. Send back to pending** writes `{ status: 'pending', approved_at: null, deposit_due_at: null, final_due_at: null }` for every application, comped or not. Invoice untouched.
- **D6. Emails.** `kind: 'approved'` reads `comped_at` and renders `approvedCompedEmail` (no deposit paragraph, no invoice total, "no balance due"). New `kind: 'comp_notice'` for an application that is already approved when comped (the drawer sends it when `app.status === 'approved' && app.approved_at` at comp time). Comping a pending application sends nothing. A "Send comp notice" button in the drawer covers the one-off for 44c185e8 after the data SQL.
- **D7. Assign Booth** loads approved applications with a left join on invoices and partitions with a pure helper `partitionAssignable(apps)` → `{ assignable, excluded: Array<{ app, reason }> }`; reasons: `no_invoice`, `deposit_not_recorded`. Comped rows are assignable by construction (milestones set) and get a "COMP" badge. Empty state lists counts per reason.
- **D9. Discount Booth has the same ordering bug** as the old comp checkbox: the discount only shapes the invoice INSERT, which only runs when no invoice exists, so approve → send back → discount → approve silently drops the discount. Fix: on approve with a discount entered and an existing invoice, `guardedWrite` an UPDATE of that invoice's `amount` to `total_amount - discount` when `amount_paid = 0` and status is pending or overdue; refused with a toast when any payment exists or the invoice is paid/cancelled. Pure helper `discountedInvoiceUpdate(invoice, totalAmount, discountCents)` → `{ amount } | { refused: string }`, tested for the sequence and the refusal. No column: the invoice amount is the discount's home.
- **D8. Data SQL** is one guarded file with two blocks and a header that states the expected pre-state of each row (business_name, status, invoice id, amount) and ABORTS on any mismatch: 13c265d7 gets `comp_application()` semantics written out by hand (comped_at now, comped_by Ryan's profile id looked up by email, invoice 0/paid/milestones, due dates null); 44c185e8 gets comped_at/by, milestones on invoice 70396b61, due dates null, amount and status untouched (already 0/paid).

### Task 2: Migration 072 + verify_072 + types

`comped_at timestamptz`, `comped_by uuid references profiles(id) on delete set null`. Both nulled in `applications_force_safe_insert()` and restored from OLD for owners in `applications_protect_staff_columns()` (071 bodies + two lines each). RPCs:

```sql
create or replace function public.comp_application(p_application_id uuid)
returns void language plpgsql security definer set search_path = public, pg_catalog as $$
declare v_inv uuid; v_total int;
begin
  if not public.is_admin() then raise exception 'not allowed' using errcode = '42501'; end if;
  select total_amount into v_total from applications where id = p_application_id for update;
  if not found then raise exception 'application not found' using errcode = 'P0002'; end if;
  update applications set comped_at = now(), comped_by = auth.uid(),
         deposit_due_at = null, final_due_at = null
   where id = p_application_id;
  select id into v_inv from invoices where application_id = p_application_id order by created_at limit 1 for update;
  if v_inv is null then
    insert into invoices (application_id, amount, amount_paid, status, paid_at, deposit_paid_at, final_paid_at)
    values (p_application_id, 0, 0, 'paid', now(), now(), now());
  else
    update invoices set amount = 0, status = 'paid', paid_at = coalesce(paid_at, now()),
           deposit_paid_at = coalesce(deposit_paid_at, now()), final_paid_at = coalesce(final_paid_at, now())
     where id = v_inv;
  end if;
end $$;
```
`uncomp_application` mirrors it: refuses when `amount_paid > 0` (`P0001`), sets comped_at/by null, invoice amount = total_amount, status pending, paid_at / milestones null. Both: `revoke all from public; grant execute to authenticated`. Applications with more than one invoice: the RPC raises `P0001 'multiple invoices'` rather than guess.

verify_072: A policies unchanged (pin the exact application/invoice policy names), B columns + functions + grants (anon has no execute), C clamp bodies contain `comped_at`, D fixtures for the three sequences + refusal + uncomp restore, as postgres with `set local role authenticated` + a claims JWT for the admin path (use Ryan's admin profile id looked up by email; abort if missing) and the harness user for the owner path, E cleanup in the last block, Z residue.
